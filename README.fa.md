# مدیریت هزینه‌ها

فارسی | [English](README.md)

یک برنامهٔ فول‌استک در حال توسعه برای ثبت درآمد و هزینه و نمایش خلاصهٔ مالی ماهانه. ساختار پروژه یک مونوریپو بر پایهٔ npm workspaces است که از کلاینت React، API مبتنی بر Hono و پایگاه‌دادهٔ PostgreSQL تشکیل شده است.

> **وضعیت پروژه:** توسعه فعال است. داشبورد و گردش‌کار تراکنش‌ها قابل استفاده‌اند، اما دسته‌بندی‌ها، تنظیمات، احراز هویت و آماده‌سازی برای محیط عملیاتی هنوز کامل نشده‌اند.

## قابلیت‌ها و محدودهٔ فعلی

قابلیت‌های پیاده‌سازی‌شده:

- ایجاد، فهرست‌کردن، دریافت، ویرایش و حذف تراکنش از طریق API.
- ایجاد، نمایش فهرست و حذف تراکنش از رابط وب.
- اعتبارسنجی داده‌های تراکنش با Zod در API و فرم ایجاد تراکنش.
- نمایش درآمد، هزینه، مانده، نمودار روزانه و پنج تراکنش اخیر ماه تقویمی جاری.
- ذخیره‌سازی داده در PostgreSQL با migrationهای Drizzle ORM.

موارد تکمیل‌نشده:

- مسیرهای Categories و Settings در حال حاضر صفحه‌های جای‌نگهدار هستند.
- API از ویرایش با `PATCH` پشتیبانی می‌کند، اما رابط وب هنوز امکان ویرایش ندارد.
- کنترل‌های فیلتر تراکنش در رابط کاربری وجود دارند، ولی هنوز روی داده‌های جدول اعمال نمی‌شوند.
- احراز هویت، سطح دسترسی، جداسازی دادهٔ کاربران، و مجموعه تست خودکار وجود ندارد.

## پیش‌نیازها

- Node.js نسخهٔ 20 LTS یا جدیدتر (پروژه اکنون با Node.js 24 بررسی شده است).

- Docker Engine به‌همراه Docker Compose برای اجرای PostgreSQL محلی.

## راه‌اندازی سریع

همهٔ دستورها را از ریشهٔ مخزن اجرا کنید.

1. وابستگی‌های workspaceها را نصب کنید.

   ```bash
   npm install
   ```

2. PostgreSQL را اجرا کنید.

   ```bash
   docker compose up -d postgres
   ```

3. فایل محیطی API را بسازید و رشتهٔ اتصال را تنظیم کنید.

   ```bash
   cp apps/api/.env.example apps/api/.env
   ```

   مقدار زیر را در `apps/api/.env` قرار دهید:

   ```env
   DATABASE_URL=postgresql://expense:expense@localhost:5432/expense_db
   ```

4. فایل `apps/web/.env` را با آدرس پایهٔ API بسازید. اسلش انتهای مقدار برای روش فعلی ساخت آدرس در کلاینت ضروری است.

   ```env
   VITE_BASE_URL=http://localhost:3000/api/
   ```

5. migrationهای ثبت‌شده در مخزن را روی پایگاه‌داده اعمال کنید.

   ```bash
   npm run db:migrate -w api
   ```

6. API و برنامهٔ وب را در دو ترمینال جدا اجرا کنید.

   ```bash
   npm run dev:api
   ```

   ```bash
   npm run dev:web
   ```

API روی `http://localhost:3000` اجرا می‌شود و Vite معمولاً برنامهٔ وب را در `http://localhost:5173` ارائه می‌کند.

برای اطمینان از اجرای API:

```bash
curl http://localhost:3000/api/health
```

پاسخ مورد انتظار:

```json
{
  "status": "ok",
  "message": "API is running"
}
```

برای متوقف‌کردن پایگاه‌دادهٔ محلی بدون حذف داده‌ها:

```bash
docker compose down
```

## پیکربندی

| فایل            | متغیر           | الزامی | توضیح                                                                                                    |
| --------------- | --------------- | ------ | -------------------------------------------------------------------------------------------------------- |
| `apps/api/.env` | `DATABASE_URL`  | بله    | رشتهٔ اتصال PostgreSQL که API و Drizzle Kit از آن استفاده می‌کنند.                                       |
| `apps/web/.env` | `VITE_BASE_URL` | بله    | آدرس پایهٔ API که در مرورگر قابل مشاهده است. باید با `/` پایان یابد؛ مانند `http://localhost:3000/api/`. |

مقادیر `VITE_*` در خروجی کلاینت قرار می‌گیرند؛ هرگز گذرواژه، کلید API یا دادهٔ محرمانه را در آن‌ها نگذارید. فایل‌های `.env` در `.gitignore` قرار دارند و `apps/api/.env.example` الگوی پیکربندی API است.

API اکنون فقط درخواست‌های cross-origin از `http://localhost:5173` را می‌پذیرد. اگر برنامهٔ وب در مبدأ دیگری اجرا می‌شود، مبدأ CORS را آگاهانه در `apps/api/src/app.ts` تغییر دهید؛ آن را برای همهٔ مبدأها باز نکنید.

## مرجع API

آدرس پایه: `http://localhost:3000/api`

| متد      | مسیر                | توضیح                                                                       | پاسخ موفق |
| -------- | ------------------- | --------------------------------------------------------------------------- | --------- |
| `GET`    | `/health`           | بررسی در دسترس‌بودن API.                                                    | `200`     |
| `GET`    | `/dashboard`        | خلاصهٔ ماه جاری، دادهٔ روزانهٔ درآمد/هزینه و پنج تراکنش آخر را برمی‌گرداند. | `200`     |
| `GET`    | `/transactions`     | همهٔ تراکنش‌ها را برمی‌گرداند.                                              | `200`     |
| `GET`    | `/transactions/:id` | یک تراکنش را با UUID برمی‌گرداند.                                           | `200`     |
| `POST`   | `/transactions`     | یک تراکنش می‌سازد.                                                          | `201`     |
| `PATCH`  | `/transactions/:id` | یک یا چند فیلد تراکنش را به‌روزرسانی می‌کند.                                | `200`     |
| `DELETE` | `/transactions`     | یک تراکنش را حذف می‌کند؛ UUID باید به‌شکل رشتهٔ JSON در body ارسال شود.     | `200`     |

### بدنهٔ تراکنش

```json
{
  "title": "خرید مواد غذایی",
  "amount": 250000,
  "category": "خوراک",
  "type": "expense"
}
```

`title` و `category` باید رشتهٔ غیرخالی باشند. مقدار `type` فقط می‌تواند `income` یا `expense` باشد. فرم ایجاد، مبلغ مثبت را الزامی می‌داند؛ API یک عدد JSON می‌پذیرد، پس فراخواننده‌ها نیز باید مبلغ مثبت و صحیح ارسال کنند. مبلغ‌ها به‌شکل integer در PostgreSQL ذخیره می‌شوند.

API برای تراکنش ذخیره‌شده، `id`، `createdAt` و `updatedAt` را اضافه می‌کند. شناسه یا بدنهٔ نامعتبر پاسخ `400` و تراکنش پیدا‌نشده پاسخ `404` می‌دهد.

### مثال‌های cURL

ایجاد تراکنش:

```bash
curl --request POST http://localhost:3000/api/transactions \
  --header 'Content-Type: application/json' \
  --data '{"title":"حقوق","amount":50000000,"category":"کار","type":"income"}'
```

ویرایش تراکنش:

```bash
curl --request PATCH http://localhost:3000/api/transactions/<transaction-id> \
  --header 'Content-Type: application/json' \
  --data '{"category":"خانه"}'
```

حذف تراکنش (API فعلی شناسه را در body JSON می‌خواهد):

```bash
curl --request DELETE http://localhost:3000/api/transactions \
  --header 'Content-Type: application/json' \
  --data '"<transaction-id>"'
```

## مدل داده و migrationها

جدول `transactions` شامل فیلدهای زیر است:

| ستون         | نوع            | توضیح                                             |
| ------------ | -------------- | ------------------------------------------------- |
| `id`         | UUID           | کلید اصلی که PostgreSQL تولید می‌کند.             |
| `title`      | `varchar(255)` | شرح تراکنش.                                       |
| `amount`     | integer        | مبلغ در کوچک‌ترین واحد پولی انتخاب‌شده در برنامه. |
| `category`   | `varchar(150)` | دسته‌بندی متنی آزاد.                              |
| `type`       | `varchar(40)`  | `income` یا `expense`.                            |
| `created_at` | timestamp      | هنگام ایجاد رکورد تنظیم می‌شود.                   |
| `updated_at` | timestamp      | هنگام تغییر رکورد به‌روزرسانی می‌شود.             |

هنگام تغییر schema:

1. schema مربوط به Drizzle را در `apps/api/src/db/schema/` تغییر دهید.
2. با `npm run db:generate -w api` یک migration ایجاد کنید.
3. SQL ایجادشده در `apps/api/drizzle/` را بررسی و همراه تغییر schema commit کنید.
4. با `npm run db:migrate -w api` آن را به‌صورت محلی اعمال کنید.

هرگز migrationی را که در یک محیط مشترک اعمال شده است ویرایش نکنید. به‌جای آن migration جدید و رو‌به‌جلو بسازید و پیش از اجرای آن در production از داده‌ها نسخهٔ پشتیبان بگیرید.

```text
.

│   │   │   └── services/     # عملیات دیتابیس و queryهای داشبورد
│   │   └── drizzle/          # migrationهای SQL نسخه‌بندی‌شده
│   └── web/
│       └── src/
│           ├── api/          # توابع HTTP کلاینت
│           ├── components/   # کامپوننت‌های layout و UI
│           ├── hooks/        # hookهای React Query
│           ├── pages/        # صفحه‌های سطح route
│           └── schemas/      # اعتبارسنجی فرم در کلاینت
├── docker-compose.yml        # سرویس PostgreSQL محلی
└── package.json              # scriptها و پیکربندی workspaceها
```

## نکات امنیتی و عملیاتی

- نام کاربری و گذرواژهٔ Docker Compose فقط برای توسعهٔ محلی هستند. در هر محیط deployشده، از اعتبارنامه‌های منحصربه‌فرد و مدیریت‌شده به‌صورت secret استفاده کنید.
- این پروژه احراز هویت یا جداسازی دادهٔ کاربران ندارد. تا زمانی که این کنترل‌ها، ارتباط امن، rate limiting، لاگ‌برداری، پشتیبان‌گیری و monitoring پیاده‌سازی نشده‌اند، آن را در اینترنت عمومی قرار ندهید و برای دادهٔ مالی حساس به کار نبرید.
- CORS را به مبدأهای شناخته‌شده محدود نگه دارید و مقادیر مخصوص هر محیط را بیرون از کنترل نسخه پیکربندی کنید.
- تا جای ممکن API و پایگاه‌داده را در شبکهٔ خصوصی ارائه کنید و پورت PostgreSQL را فقط در صورت نیاز منتشر کنید.
- migrationها بخشی از فرآیند deploy هستند. پیش از استفاده در production از پایگاه‌داده پشتیبان بگیرید و migration را روی نمونه‌ای مشابه دادهٔ واقعی آزمایش کنید.
